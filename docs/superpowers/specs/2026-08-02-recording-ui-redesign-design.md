## 一句話目標

把陽春的錄音頁改成參考元件（AI Voice Input）的極簡樣貌——中央麥克風按鈕、等寬計時器、48 根音量長條、下方文字控制項——並讓長條由真實麥克風音量驅動；不引入任何新依賴。

## 參考來源與技術落差

使用者提供的參考是一個 React 元件（`ai-voice-input.tsx`），要求 React + TypeScript + Tailwind + shadcn + lucide-react。本專案是 Express 直接送靜態檔的原生 HTML/JS，**無任何建置流程**，依賴僅 4 個後端套件。

**決策：只移植視覺，不移植技術棧。** 該元件的視覺（圓角方形按鈕、mono 計時器、48 根 2px 長條、狀態文字）純 CSS 即可一比一重現；引入前端工具鏈會違反 v1.1 訂下的「不引入重量級相依」約束，並牽動 `scripts/build-app.sh` 與啟動流程。

**同時修正參考元件的一個缺陷**：它的長條高度是 `Math.random()` 加 `animate-pulse`，純裝飾。本專案已有 `AnalyserNode`，改為真實頻譜驅動。

## 影響範圍

**修改**：
- `public/index.html` — 重寫標記與樣式。CSS 由內嵌約 60 行成長到約 200 行，**仍留在單檔內**（維持零建置、單次請求）。

**不動**：`src/`、`test/`、`scripts/`、`package.json`、`README.md` 的安裝與費用章節。

### app.js 的三處調整

1. `drawWave()` / `stopWave()`：從單一 canvas 長條改為驅動 48 個 DOM `<span>`。
2. 移除 `setStep()`：處理中頁改為單行固定文字，不再需要逐步驟切換 class。
3. `renderDone()`：配合新標記（`#done-title`、常駐的 `#preview`、文字樣式的結果連結）。
4. `togglePause()`：按鈕文字 `⏸ 暫停` / `▶ 繼續` → `Pause` / `Resume`；**移除對 `rec-label` 的兩行寫入**（見下）。
5. `restartRecording()`：由原生 `confirm()` 改為開啟自訂 `<dialog>`，實際歸零邏輯抽成獨立函式供對話框的確認鈕呼叫。

### 元素 id 沿用

`title`、`btn-start`、`btn-pause`、`btn-stop`、`btn-restart`、`btn-new`、`btn-retry`、`timer`、`result-link`、`preview`、`err`、四個 `view-*` 容器 — **全數沿用**（`s-upload` / `s-analyze` / `s-write` 隨三步驟清單一併移除，改為單一 `.proc-stage` 元素），把 app.js 改動壓到最小。

**結構性變動（三處，實作時必須同步改 app.js）**：

| 變動 | 說明 |
|---|---|
| `<canvas id="wave">` → `<div id="wave">` | 內含 48 個 `<span class="bar">`；`drawWave()` 改寫入目標 |
| **移除 `rec-label`** | 原本顯示「錄音中／已暫停」的文字，其位置在新設計中由 `Pause` / `Resume` 按鈕取代（狀態已由按鈕文字表達）。`togglePause()` 內兩行 `$('rec-label').textContent = ...` 必須一併刪除，否則會拋出 null 錯誤 |
| **新增 `rec-title`、`done-title`、`proc-stage`** | 前兩者為錄音中與完成頁的會議標題靜態顯示（開始錄音時由 `#title` 寫入 `rec-title`；`renderDone()` 寫入 `done-title`）。`rec-title` 在標題為空時用 `.is-empty`（`visibility: hidden`）保留槽位。`proc-stage` 為處理中頁的單行文字 |

## 版面設計

### 共用骨架

480×720 直式小窗，單欄、水平置中；垂直方向**靠上對齊**（`body` 用 `align-items: flex-start` + `padding-top: 70px`），視窗被拉高時版面不會跟著往下飄。70px 取自 `(720 − 580) / 2`，讓預設視窗維持原先垂直置中的視覺位置。四狀態共用同一條視覺軸線，切換時只有中央區塊與下方控制項變化，視覺重心不跳動。

**版面位置穩定（硬性要求）**：切換狀態時，中央大按鈕與其上方的所有元素**不得產生任何垂直位移**。做法：

- `.stage` 設固定 `min-height: 580px`（取自最高的完成頁：兩行標題時約 568px），內容自固定頂端起排（`justify-content: flex-start`），使外框高度不隨內容變動，垂直置中的結果因此恆定。
- 標題槽**最多兩行**，三個標題元素共用同一組規格：`min-height: calc(1.4em + 13px)`（＝一行行高 + 12px padding + 1px 底線）、`margin-bottom: 52px`、`line-height: 1.4`。
  - 待機頁改用 `<textarea>`（`<input>` 在規格上無法顯示兩行），高度由 JS 依行數自動調整，上限兩行；超過兩行時於欄位內捲動，讓使用者仍看得到自己輸入的內容。Enter 鍵不插入換行。
  - 錄音頁與完成頁為 `-webkit-line-clamp: 2`，超過兩行以 `…` 截斷。
- `min-height` 取**一行的完整高度**而非湊整數，是為了讓「空標題」與「一行標題」在三個狀態下高度完全相同，否則未填標題時切換仍會位移。
- 兩行上限讓標題區塊的高度有界，因此**長標題不會再推動麥克風**——一行對一行、兩行對兩行，位移消失。
- `.stage` 的 `min-height` 為 `580px`：完成頁在標題佔滿兩行時總高約 568px，需要這個餘裕才不會被撐開。
- 三個標題元素（`.title-input` / `.rec-title` / `.done-title`）的**盒模型必須完全一致**（相同的 `height`、`padding` 與 `border-bottom`），否則 `<input>` 與 `<div>` 的文字中心會有次像素落差，切換時看得出微幅位移。
- 標題為空時，`.rec-title` 以 `visibility: hidden` 保留空間，**不得用 `display: none`**（後者會抽掉整個槽位造成上移）。
- 下方控制項的數量在各狀態不同是允許的——因為採頂端對齊，它們的高度差不會推動上方元素。
- 完成頁的摘要高度固定 `400px` 且自身捲動，不得撐破 `.stage` 的固定高度。

**垂直節奏（實作時的間距規格）**：

```
標題
   ↕ 32px
中央大按鈕（64×64）
   ↕ 8px
計時器
   ↕ 8px
visualizer（48 根長條，bar 寬 3px、間距 3px，容器 288×24px；較參考元件等比放大 1.5 倍）
   ↕ 20px
主控制項（Pause / Click to speak）
   ↕ 20px
次控制項（Restart）
```

`8px` 群組維持參考元件的緊湊感；`20px` 為使用者指定值，套用於 visualizer 之下與兩個控制項之間。

            00:00             ← 等寬字，30% 不透明

- 標題輸入無邊框，僅置中文字與 placeholder「會議標題（選填，空白就讓 AI 命名）」。（留空時後端 `decideTitle()` 會優先採用 Gemini 依內容建議的標題，兩者皆無才用日期；文案依此行為撰寫。）
- 點中央按鈕 = 開始錄音（沿用 `btn-start`）。

```
          會議標題             ← 有填才顯示，轉為靜態文字
             ◼                ← 旋轉方塊（3 秒一圈），橘粉漸層

- 中央旋轉方塊 = 停止並分析（`btn-stop`）。為避免「不知道要點它」，按鈕加 `title="停止並分析"` 屬性（原生 tooltip，不另寫 CSS）與 `aria-label`。

```
        （距內容區頂端 200px）
        ■ ■ ■   ← 三顆方塊階梯式跳動（18px，間距 9px，圓角 2px）
             ↕ 20px
      Analyzing with Gemini…  ← 單行固定文字，置中

- 中央為**三顆方塊的階梯式跳動**（`.ld-stairs`，依序延遲 0 / .15s / .3s，1.2s 循環），與下方文字間距 `20px`。方塊沿用橘粉漸層，與錄音頁的旋轉方塊、音量長條同一套語彙。
  - 尺寸為參考來源的 1.5 倍：方塊 18px、間距 9px、跳躍高度 21px（與 visualizer 的放大倍率一致），圓角 2px。
  - 原本的脈動漸層圓環（`.ring` + `@keyframes pulse`）已由此取代，相關 CSS 一併移除。
- 與其他三頁一樣**靠上固定**：載入動畫距內容區頂端 `200px`（`.ld-stairs` 的 `margin-top`），視窗高度改變時位置不動。曾短暫改為垂直置中於 `.stage`，實測後改回靠上固定。
  - 其他三個狀態仍維持「內容自固定頂端起排」，因為它們彼此之間有需要對齊的共用元素（標題、麥克風按鈕）；處理中頁沒有這類元素，置中不會造成對齊問題。
- **不再是三行打勾清單**，改為**單行固定文字** `Analyzing with Gemini…`，水平置中對齊圓環。
- **不做階段性文字變化**。曾評估過兩段式（`Uploading audio…` → `Analyzing with Gemini…`），因上傳到 localhost 幾乎瞬間完成、第一段只會一閃而過，實測後決定捨棄。
- 因此 `sendForProcessing()` 維持使用 `fetch`（改用 XHR 的唯一理由是取得上傳完成訊號，已不需要）。

## 波形的真實音量驅動

現行 `drawWave()` 把整個頻譜平均成單一數值、畫成一根 canvas 長條。改為：

1. 每幀 `analyser.getByteFrequencyData(data)`。
2. 依**對數頻段**把頻譜切成 48 段，各段取平均。
3. 經 `WAVE_GAMMA = 1.8` 的指數曲線後映射到 **12%–100%** 的高度區間，以 `transform: scaleY()` 寫進對應 `<span>`（GPU 合成，48 元素 60fps 不卡）。

**起伏幅度的調校**：`AnalyserNode` 的預設值會讓整排長條看起來一樣高——`smoothingTimeConstant` 預設 0.8，每幀與前幀混合過重而抹平差異；`minDecibels/maxDecibels` 預設 -100/-30，一般說話全擠在中段。因此改為 `smoothingTimeConstant = 0.6`、`minDecibels = -85`、`maxDecibels = -25`，並加上 gamma 曲線。三者中以「降低平滑」與「抬高噪音底線（安靜的頻段真的歸零）」的效果最明顯；gamma 主要是把中低段壓低以增加對比。

**為何是對數而非線性**：`AnalyserNode` 的 1024 個頻率格涵蓋 0 至取樣率的一半（通常 24kHz），但人聲能量幾乎全在 4kHz 以下。線性切分會讓後面四十根長條落在幾乎無訊號的高頻段、看起來像壞掉。改以 `60Hz – 6000Hz` 的對數邊界分配（`WAVE_MIN_HZ` / `WAVE_MAX_HZ`），低頻取得較多長條、高頻壓縮，48 根都落在有內容的範圍內。低頻端相鄰邊界可能落在同一格，以 `Math.max(from + 1, …)` 保證每根至少取一格、不會除以零。

`requestAnimationFrame` 迴圈骨架與 `startRecording()` 內的 `AudioContext` / `AnalyserNode` 建立流程完全照舊。

**暫停行為天然成立**：`stopWave()` 停止 rAF 但不重設高度，長條即凍結在最後狀態——正是暫停態要的視覺，無需額外程式碼。

## 配色與明暗

- 黑白層級以 CSS 變數定義（文字、次要文字、邊框、底色四級），深淺色各一組，由 `prefers-color-scheme: dark` 切換。
- 橘粉漸層為單一組色值，深淺色共用，僅用於兩處：錄音中的旋轉方塊與長條、處理中的脈動圓環。（完成頁改為純文字控制項後不再使用漸層。）
- 漸層色值：實作時自 `assets/icon.png` 取樣橘、粉兩個端點色，寫成 `--grad-from` / `--grad-to` 兩個 CSS 變數，所有漸層引用這兩個變數（日後換圖示只需改兩行）。

## 必須保留的既有行為

實作時逐項確認未被破壞：

- 麥克風權限失敗的繁中錯誤訊息。
- `/api/process` 失敗後回到可操作狀態並保留 `lastBlob` 供重試。
- `pagehide` 送 `navigator.sendBeacon('/shutdown')`（「關窗即結束」的關鍵）。
- Notion / `.md` 兩種輸出分支的顯示差異。
- `esc()` 對摘要與重點的 XSS 跳脫。
- `Restart` 前的確認（實作由原生 `confirm()` 改為自訂 `<dialog>`，但「必須先確認才丟棄錄音」這個行為不變）。

## 測試策略

前端無自動化測試，沿用 v1.1 做法：

**回歸防護**：`npm test` 應維持 40 / 40 全綠（後端未動）。

**手動清單**：
- [ ] 四狀態切換正確：待機 → 錄音中 → 處理中 → 完成 → New AI Note 回到待機。
- [ ] 暫停：方塊停轉、計時器停走、長條凍結、文字變 `Resume`；繼續後三者恢復。
