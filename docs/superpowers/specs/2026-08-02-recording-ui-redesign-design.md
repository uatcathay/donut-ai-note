## 一句話目標

把陽春的錄音頁改成參考元件（AI Voice Input）的極簡樣貌——中央麥克風按鈕、等寬計時器、48 根音量長條、下方文字控制項——並讓長條由真實麥克風音量驅動；不引入任何新依賴。

## 參考來源與技術落差

使用者提供的參考是一個 React 元件（`ai-voice-input.tsx`），要求 React + TypeScript + Tailwind + shadcn + lucide-react。本專案是 Express 直接送靜態檔的原生 HTML/JS，**無任何建置流程**，依賴僅 4 個後端套件。

**決策：只移植視覺，不移植技術棧。** 該元件的視覺（圓角方形按鈕、mono 計時器、48 根 2px 長條、狀態文字）純 CSS 即可一比一重現；引入前端工具鏈會違反 v1.1 訂下的「不引入重量級相依」約束，並牽動 `scripts/build-app.sh` 與啟動流程。

**同時修正參考元件的一個缺陷**：它的長條高度是 `Math.random()` 加 `animate-pulse`，純裝飾。本專案已有 `AnalyserNode`，改為真實頻譜驅動。

## 已定案的設計決策

| 項目 | 決定 |
|---|---|
| 技術路線 | 純 CSS 移植，零新依賴，維持原生 HTML/JS |
| 配色 | 黑白極簡分層 + 橘粉漸層點綴（呼應 App 圖示） |
| 明暗 | 跟隨系統 `prefers-color-scheme` |
| 停止並分析 | 中央大按鈕（錄音時為旋轉方塊）即停止鈕 |
| 文案語言 | 按鈕用英文（Pause / Resume / Restart / Click to speak），其餘長句維持繁體中文 |
| 會議標題 | 保留，待機頁中央按鈕上方的無框輸入 |
| 完成頁摘要 | 預設摺疊，點「查看摘要」展開 |

## 非目標（YAGNI）

- 不改後端（`src/`）、不改測試（`test/`），現有 40 個自動化測試維持全綠。
- 不改錄音流程：四狀態、六個動作、輸出目的地邏輯皆不變。
- 不引入 React / Tailwind / TypeScript / 任何建置步驟或 CDN 依賴。
- 不改 `scripts/`（打包與啟動器）與 `Info.plist`。
- 不做前端自動化測試（沿用 v1.1 的手動清單做法）。

## 影響範圍

**修改**：
- `public/index.html` — 重寫標記與樣式。CSS 由內嵌約 60 行成長到約 200 行，**仍留在單檔內**（維持零建置、單次請求）。
- `public/app.js` — 邏輯流程不變，僅三處調整（見下）。

**不動**：`src/`、`test/`、`scripts/`、`package.json`、`README.md` 的安裝與費用章節。

### app.js 的三處調整

1. `drawWave()` / `stopWave()`：從單一 canvas 長條改為驅動 48 個 DOM `<span>`。
2. `setStep()` 與 `renderDone()`：配合新標記（步驟圖示改由 CSS 呈現、完成頁多一層摺疊容器與標題顯示）。
3. `togglePause()`：按鈕文字 `⏸ 暫停` / `▶ 繼續` → `Pause` / `Resume`；**移除對 `rec-label` 的兩行寫入**（見下）。

### 元素 id 沿用

`title`、`btn-start`、`btn-pause`、`btn-stop`、`btn-restart`、`btn-new`、`btn-retry`、`timer`、`s-upload`、`s-analyze`、`s-write`、`result-link`、`preview`、`err`、四個 `view-*` 容器 — **全數沿用**，把 app.js 改動壓到最小。

**結構性變動（三處，實作時必須同步改 app.js）**：

| 變動 | 說明 |
|---|---|
| `<canvas id="wave">` → `<div id="wave">` | 內含 48 個 `<span class="bar">`；`drawWave()` 改寫入目標 |
| **移除 `rec-label`** | 原本顯示「錄音中／已暫停」的文字，其位置在新設計中由 `Pause` / `Resume` 按鈕取代（狀態已由按鈕文字表達）。`togglePause()` 內兩行 `$('rec-label').textContent = ...` 必須一併刪除，否則會拋出 null 錯誤 |
| **新增 `rec-title`、`done-title`** | 錄音中與完成頁的會議標題靜態顯示。開始錄音時由 `#title` 的值寫入 `rec-title`；`renderDone()` 寫入 `done-title`。兩者在標題為空時隱藏（`hidden` class） |

## 版面設計

### 共用骨架

480×720 直式小窗，單欄、水平置中、垂直置中。四狀態共用同一條視覺軸線，切換時只有中央區塊與下方控制項變化，視覺重心不跳動。

**垂直節奏（實作時的間距規格）**：

```
標題
   ↕ 32px
中央大按鈕（64×64）
   ↕ 8px
計時器
   ↕ 8px
visualizer（48 根長條，寬 256px，高 16px）
   ↕ 20px
主控制項（Pause / Click to speak / 步驟清單 / 完成資訊）
   ↕ 20px
次控制項（Restart / 記錄新會議）
```

`8px` 群組維持參考元件的緊湊感；`20px` 為使用者指定值，套用於 visualizer 之下與兩個控制項之間。

### 狀態一：待機（`view-idle`）

```
        會議標題（選填）        ← 無框置中輸入，focus 時底線亮起
             🎙               ← 64×64 圓角方塊，hover 淡底
            00:00             ← 等寬字，30% 不透明
      ▁▁▁▁▁▁▁▁▁▁▁▁▁▁        ← 48 根靜止細條，高 4px，10% 不透明
        Click to speak        ← 12px，70% 不透明
```

- 標題輸入無邊框，僅置中文字與 placeholder「會議標題（選填，空白就用日期）」。
- 點中央按鈕 = 開始錄音（沿用 `btn-start`）。

### 狀態二：錄音中（`view-recording`）

```
          會議標題             ← 有填才顯示，轉為靜態文字
             ◼                ← 旋轉方塊（3 秒一圈），橘粉漸層
            00:42             ← 70% 不透明
      ▃▅▇▂▅▇▃▁▆▄▂▇▅         ← 真實音量驅動，橘粉漸層
           Pause
             ↕ 20px
          Restart
```

- 中央旋轉方塊 = 停止並分析（`btn-stop`）。為避免「不知道要點它」，按鈕加 `title="停止並分析"` 屬性（原生 tooltip，不另寫 CSS）與 `aria-label`。
- `Restart` 沿用既有確認對話框。

### 狀態三：暫停（錄音中的子狀態）

```
          會議標題
             ◼                ← 停止旋轉；仍可點 = 停止並分析
            00:42             ← 停在暫停當下的秒數
      ▃▅▇▂▅▇▃▁▆▄            ← 長條凍結在最後高度
           Resume             ← 就地取代 Pause，同元素只換文字
             ↕ 20px
          Restart             ← 不變
```

控制項的數量與位置在錄音／暫停之間完全不變，僅方塊停轉、文字換字，版面不位移。

### 狀態四：處理中（`view-processing`）

```
        （脈動的漸層環）
      ✓ 上傳音檔
      ⟳ Gemini 分析中（逐字稿＋摘要＋重點）
      ○ 寫入輸出
```

中央換成緩慢脈動的橘粉圓環（呼應 App 圖示的甜甜圈造型）。三步驟沿用現有 `done` / `active` / `pending` 三態與繁中文案。

### 狀態五：完成（`view-done`）

```
        （橘粉漸層勾勾）
          會議標題
    [ 開啟 Notion 記錄 ]      ← 主按鈕，橘粉漸層填色
        查看摘要 ⌄            ← 預設摺疊
        ＋ 記錄新會議
```

- 展開後顯示摘要與重點清單，該區塊 `max-height` + `overflow-y: auto`，長摘要不會把下方按鈕擠出畫面。
- 未設定 Notion 時，主按鈕位置改為顯示 `.md` 檔路徑（沿用現有分支邏輯）。
- 摺疊以 `<details>/<summary>` 實作（原生、無需 JS）。

### 錯誤區塊

`#err` 沿用現有位置與顯示邏輯，樣式改為與新視覺一致的紅色淡底卡片；`btn-retry`（用同一段錄音重試）維持既有出現條件。

## 波形的真實音量驅動

現行 `drawWave()` 把整個頻譜平均成單一數值、畫成一根 canvas 長條。改為：

1. 每幀 `analyser.getByteFrequencyData(data)`。
2. 把頻譜切成 48 段，各段取平均。
3. 映射到 **20%–100%** 的高度區間，以 `transform: scaleY()` 寫進對應 `<span>`（GPU 合成，48 元素 60fps 不卡）。

`requestAnimationFrame` 迴圈骨架與 `startRecording()` 內的 `AudioContext` / `AnalyserNode` 建立流程完全照舊。

**暫停行為天然成立**：`stopWave()` 停止 rAF 但不重設高度，長條即凍結在最後狀態——正是暫停態要的視覺，無需額外程式碼。

## 配色與明暗

- 黑白層級以 CSS 變數定義（文字、次要文字、邊框、底色四級），深淺色各一組，由 `prefers-color-scheme: dark` 切換。
- 橘粉漸層為單一組色值，深淺色共用，僅用於三處：錄音中的旋轉方塊與長條、處理中的脈動圓環、完成頁的勾勾與主按鈕。
- 漸層色值：實作時自 `assets/icon.png` 取樣橘、粉兩個端點色，寫成 `--grad-from` / `--grad-to` 兩個 CSS 變數，所有漸層引用這兩個變數（日後換圖示只需改兩行）。

## 必須保留的既有行為

實作時逐項確認未被破壞：

- 麥克風權限失敗的繁中錯誤訊息。
- `/api/process` 失敗後回到可操作狀態並保留 `lastBlob` 供重試。
- `pagehide` 送 `navigator.sendBeacon('/shutdown')`（「關窗即結束」的關鍵）。
- Notion / `.md` 兩種輸出分支的顯示差異。
- `esc()` 對摘要與重點的 XSS 跳脫。
- `Restart` 的確認對話框。

## 測試策略

前端無自動化測試，沿用 v1.1 做法：

**回歸防護**：`npm test` 應維持 40 / 40 全綠（後端未動）。

**手動清單**：
- [ ] 四狀態切換正確：待機 → 錄音中 → 處理中 → 完成 → 記錄新會議回到待機。
- [ ] 暫停：方塊停轉、計時器停走、長條凍結、文字變 `Resume`；繼續後三者恢復。
- [ ] 暫停中點中央方塊可直接停止並分析。
- [ ] Restart：跳確認框，確認後歸零回待機。
- [ ] 長條隨真實說話音量起伏（不是隨機跳動）。
- [ ] 端到端：錄音 → Gemini 分析 → 寫入 Notion 資料庫一列，或桌面 `.md`。
- [ ] 完成頁摘要摺疊／展開；用長摘要驗證下方按鈕不被擠出畫面。
- [ ] 深色與淺色模式各檢視四狀態一次。
- [ ] 480×720 小窗下無橫向捲軸。
- [ ] 麥克風權限拒絕時顯示正確訊息。
- [ ] 關閉視窗後 `lsof -ti:3000` 無殘留。
